# Bundled npm lock migration after PR #11

## Reproduced problem

Old APKs did not bundle every package-lock.json. The runtime's npm install can create that file on the phone. PR #11 adds reproducible lockfiles to the bundled packages. The safe installer treated the new lock's collision with the old local file as a user-source conflict and preserved the entire old extension.

Two regression tests reproduced this before changing production code: PR Check run 35075854502, Android job 104728016393, 252 app tests completed with exactly the two expected migration assertion failures. Existing shared tests and runtime/package typechecks passed.

## Narrow migration

Only for an identifiable bundle whose previously tracked sources still match their hashes, an untracked root package-lock.json may transition to the APK's managed lock. Its original bytes are first archived in the installer's state directory outside extension discovery as `<package>.npm-lock-<sha256>.json`. The archive is verified and the original file is checked again before the directory swap. No existing archive is overwritten. A failed backup leaves the installed package intact.

This is a provenance rule, not a claim that every untracked lock was generated by npm: even a manually supplied untracked lock is retained byte-for-byte in the archive. A modified previously managed lock is not replaced. Changed sources, unknown imports, symlinks and all other extra-file collisions keep their existing protections.

Existing configuration files and the dependency tree are preserved during the atomic bundle swap. The runtime's separately tested manifest/lock/runtime fingerprint handles dependency refresh afterwards. Repeated launches do not create duplicate archives. Nothing resets Alpine, chat history, credentials or app data.

## Verification

Five targeted tests cover legacy migration, managed-bundle migration, edited sources, edited managed locks and a conflicting/corrupt archive. The previous installer tests continue to cover unrelated file collisions, unknown imports, symlinks, interrupted copies and directory-swap recovery. Final-head CI results must be green before merge and are recorded in PR #12.

No package ID, signing, version configuration, language resources, model-facing schemas or Nightly workflow changes are included. R06, R08 and R11 remain outside this migration fix.
